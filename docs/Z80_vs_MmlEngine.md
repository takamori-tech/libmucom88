# MUCOM88互換性と検証

libmucom88はMUCOM88形式のMMLをネイティブC++で解釈・再生する実装です。
オリジナルのZ80コンパイラやドライバーを実行する方式ではありません。
この文書は、現在の処理構造、再現時に注意する差、検証の範囲を示します。

## 参照先

- [MUCOM88公式ページ（株式会社エインシャント）](https://www.ancient.co.jp/~mucom88/)
- [Open MUCOM88](https://github.com/onitama/mucom88): Z80ソース、VM、音源処理を調べる参照実装。
- 本リポジトリの [MmlParser](../include/mucom88/mml_parser.hpp) と [MmlEngine](../include/mucom88/mml_engine.hpp)

比較を実行する際はOpen MUCOM88側のrevision・ドライバー版も記録します。
本書のコード照合だけで、全楽曲や全コマンドの一致を検証済みとはしません。

## 処理構造の違い

| 観点 | Z80ドライバーを使う参照経路 | libmucom88 |
| --- | --- | --- |
| MMLの変換 | コンパイラでドライバー用データへ変換 | `MmlParser` が `MmlEvent` 列へ変換 |
| 演奏 | Z80ドライバーがデータを解釈 | `MmlEngine` がイベントを処理 |
| 音源制御 | VMのI/Oを音源へ接続 | `IFmEngine::writeReg()` を呼ぶ |
| 時刻 | VMと音源のタイマー | ソフトウェアのTimer-Bカウンタ |
| PCM | 参照環境の音源処理 | 利用側のバックエンド、または付属ymfmアダプタ |
| メモリ | VM・ドライバーの配置に依存 | 文字列・vector等のコンテナ。有限のメモリと展開コストを持つ |

開始までの遅延、音源エミュレータ、出力段の違いを分けて比較します。
一定の開始遅延や書き込み数の差だけから、音質への影響の有無を断定しません。

## 現在のMML処理

### トラック

| トラック / index | 音源 |
| --- | --- |
| A–C / 0–2 | FM1–3 |
| D–F / 3–5 | SSG1–3 |
| G / 6 | ADPCM-Aリズム |
| H–J / 7–9 | FM4–6 |
| K / 10 | ADPCM-B |

`MmlParser::MucFile` は `#mode` とその明示有無を保持しますが、
`MmlEngine::loadFromParseResult()` はそれを使ってチップやトラック配置を変更しません。
`ChipMode` の存在は、各チップでの再現が同じ範囲まで実装・検証されているという意味ではありません。

### テンポとTimer-B

| 記法・API | 現在の意味 |
| --- | --- |
| `T120` | BPMを指定。整数手順でTimer-B値へ変換してTEMPOイベントを生成 |
| `t200` | Timer-B値を直接指定 |
| `C128` | 全音符を128クロックとして音長・BPM変換に使用 |
| `TEMPO.value` / `globalTempo()` | BPMではなくTimer-B値 |

`recalcTimerB()` は固定の整数式 `7987200 / 2 / 6 / 12 = 55466` を使い、
周期の整数切り捨ても行います。`init()` / `setChipClock()` のクロック指定でこの式は変わりません。
非標準クロックを指定したときの音高換算とテンポ換算を同一視しないでください。

`advance()` はTimer-B tickごとにレジスタ0x27へ0x3A、CSM状態では0x7Aを書きます。
「初期化時に一度だけ書く」という旧説明は現行実装に当てはまりません。
タイマー制御の一致を調べる場合は、イベント時刻とレジスタトレースを併せて比較します。

### 音長・ループ・マクロ

- 音長はMUCOM88のクロックをtickとして扱います。既定の全音符は128tickです。
- `q0` は早切りなしの指定です。通常ノート終端のNOTE_OFFが消えるという意味ではありません。
- `%N` は既定音長のクロック指定として処理され、その場で時刻を進める命令ではありません。
- `[ ... ]N` は解析時にイベントへ展開されます。`L` は演奏時の曲ループ位置です。
  `loadFromParseResult()` は `L` があるとループを有効にするため、一回再生はロード後に `setLoop(false)` を指定します。
- マクロは `#*N{...}` で定義し、`*N` で参照します。
- LFO・SSGエンベロープ・ポルタメント・リバーブ・ハードウェアLFO・CSM等は
  対応イベントと処理経路を持ちます。列挙子や分岐の存在だけで全派生文法の互換性は保証しません。

SSGの発音には内蔵プリセット `@0` など、または `E` でエンベロープを設定します。
現行の初期値では音符・音量だけを指定しても振幅は0です。

正確なフィールド解釈は [APIリファレンス](api_reference.md#mmlevent) と
パーサー・シーケンサーの処理を確認します。ソース冒頭の古い説明コメントと実際の処理が異なる場合は、
実装・再現試験を根拠にします。

### 入力とデータの境界

`parse()` は構文診断一覧や成功フラグを返しません。未知の文字を読み飛ばす場合があります。
音長・タイ境界・マクロ再帰の一部に制限はありますが、入力全体のサイズ・総イベント数・
実行時間を完全に制限するAPIではありません。

FM音色、リズムROM、ADPCM-Bデータは結果に影響します。`#voice` / `#pcm` のメタデータを読むだけで
同じファイルがロードされるわけではありません。組み合わせるデータを固定して比較します。

## PCMと音量の比較条件

通常の `renderMixed()` は最大16フレームずつMML、ボイス、SE、PCM生成を進めます。
バックエンドだけを直接生成する比較と、Tuned出力段を含む比較を区別します。

比較記録には次を含めます。

| 条件 | 記録する内容 |
| --- | --- |
| ソース | libmucom88・参照実装・バックエンドのrevision、変更差分 |
| 入力 | MML、音色、PCM、ROMの識別子・ハッシュ、対象トラック |
| 時刻 | サンプルレート、クロック、生成フレーム数、開始位置の合わせ方、ループ条件 |
| 音量 | Native/Tuned、SSG倍率、outputGain、較正、DAC・リミッターの設定 |
| 結果 | 実行コマンド、終了コード、成功・除外件数、指標、出力とログ |

RMS比は音量の近さを測る指標です。比が1でも、ノートの欠落、位相差、タイミング差がない証明にはなりません。
必要に応じてレジスタ列、ノート時刻、PCM差分も調べます。

## 本リポジトリで実行できる検証

単体テストのコマンドは [開発規約](../CLAUDE.md#テスト) を参照してください。
現在の登録は [CMakeLists.txt](../CMakeLists.txt) にあり、ツール有効時は8件、無効時は7件です。

| テスト | 主な対象 |
| --- | --- |
| `adpcm_a_roundtrip` | ADPCM-A変換 |
| `chip_calibration` | 音源較正 |
| `mml_render_mixed_limit` | 混合出力とリミッター |
| `mml_portamento_octave` | ポルタメントのオクターブ |
| `logical_stem_mixer` | パート別double加算 |
| `post_chip_processor` | 後段音声処理 |
| `regression_metrics` | 回帰比較の指標計算 |
| `drumkit_gen_wavparse` | ツールのWAV入力処理。ツール有効時のみ |

これらはZ80参照との全曲比較、任意バックエンドの正しさ、DAWや実音を包括する試験ではありません。
`muc_regtest` / `muc_compare` は本リポジトリのビルドターゲットではありません。
全曲比較を持つ利用側環境がある場合は、その環境の規約と入力に従って追加確認します。

互換性の開発目標は [開発規約](../CLAUDE.md#mml再現目標) を参照してください。
未実行は `skip`、不明は `Unknown`、実音・操作感は利用者確認まで `NOT_VERIFIABLE` として、
コード照合と実行結果を区別します。
